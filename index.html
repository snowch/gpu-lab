LAB 01 / MEMORY ACCESS

Same values. Different addresses.

Interactive draft

Imagine reading one feature from each row of a tensor. A GPU runs many copies of a small program, called a kernel. Each copy is a thread. NVIDIA GPUs organise threads into groups of 32 called warps.

Here, one warp reads 32 values. Each thread reads one 32-bit floating-point value (FP32), which occupies four bytes. Its position within the warp is its lane, numbered 0 to 31.

Memory requests from a warp can be combined into aligned regions. This model groups addresses into 32-byte sectors: bytes 0–31, then 32–63, and so on. This grouping is called coalescing. Your task is to see how the addresses determine the sectors touched.

What this model tells you

We count distinct aligned 32-byte sectors touched by one warp’s global-memory load, with four-byte aligned FP32 values and a sector-aligned base pointer. This matches the coalescing accounting described for devices of compute capability 6.0 or newer in NVIDIA’s CUDA Best Practices Guide.

These counts are not DRAM transactions or elapsed time. Caches, reuse between warps, stores, instruction issue, and memory-controller behaviour are outside this model. A sector diagram does not show execution order. More sectors can increase memory traffic; it does not imply a proportional slowdown.

CONNECT THE MODEL TO CODE

A small CUDA kernel.

CUDA lets you write the program each GPU thread runs. This kernel copies selected input values into consecutive output positions. Change stride or offset above and the input indexing below changes with it.

Threads are also grouped into blocks. Here, threadIdx.x is a thread’s index in its block; blockIdx.x identifies the block; blockDim.x is its thread count. Together they calculate i, the output index.

The simulator shows the input load for the first warp of the first block. Its active-lane control corresponds to a bound n smaller than a warp. The output store is not counted.

TRY IT YOURSELF

Make a prediction you can explain.

  1. Choose Tensor column. Think of a row-major tensor with eight features per row. The warp reads the same feature from successive rows. Predict the sector count, then check it.
  2. Switch to Contiguous. Now it reads neighbouring features. Compare requested bytes and sector coverage. Which changed?
  3. Choose Shift by one. Explain what happens at the two ends of the address range.
  4. Set 8 active lanes, stride 1, and offset 0. Predict what changes if you move the offset to 1.
Explain the result in your own words, then compare

Each sector holds eight FP32 values. Neighbouring lanes can use different values in the same sector. With a stride of eight elements, each lane reaches a different sector. Shifting a consecutive range by one element can make it cross an extra sector boundary.

In an AI workload, changing how threads map onto tensor dimensions can change this access pattern. A transpose or a different tensor layout may help one operation and add costs elsewhere. Count the work across the whole operation before choosing a layout.
