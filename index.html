ARCHITECTURE OVERVIEW · ABOUT FIVE MINUTES

Meet the GPU

A PyTorch operation such as y = x + 1 looks simple. When x is a CUDA tensor, PyTorch arranges for GPU work to read its values, add one, and write the result. Here is the machine that executes that work.

A thread is one instance of a GPU program. Many threads can execute the same program on different tensor elements.

Open each layer to look inside. This map follows the NVIDIA CUDA architecture used in the labs.

1. The system: where tensors live

Memory holds the numbers; processors execute the work. A tensor also has metadata, such as its shape and strides, describing how to interpret those numbers. Lab 01 starts there.

2. Inside the GPU: many places to execute work

The GPU can keep other work moving while some threads wait for data. How well it does that depends on having enough ready work and resources to hold it.

3. How work maps onto the machine

A kernel is a GPU function. A launch creates a grid of thread blocks to execute it. Follow one block from that grid into an SM, then look inside its warps.

Example: four blocks, 64 threads per block, two SMs. Placement is chosen to show the relationships; this is not a scheduling simulation or a hardware-capacity claim.

Following block A on SM 0, warp 0.

You do not need to memorise these terms. The labs revisit them when they explain a tensor operation.

What makes a GPU fast?

Running many threads in parallel helps when they have useful work and can get the data they need. Moving data, waiting for dependencies, and taking different instruction paths all affect how much work the GPU completes.

Follow the map through memory access, scheduling, different paths, cooperation, data reuse, and tensor cores. Then apply those ideas to attention and inference.
