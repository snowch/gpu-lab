Repair a kernel

Repair a kernel, explain its failures, then build vector addition.

Begin with y = 2 * x, then transfer what you learn to y = x + b: the elementwise addition used in residual connections in neural networks.

A kernel is a function run many times; one run is an thread. An thread with a valid element index should write one output value. Array indices start at zero.

Guided challenges

Start a challenge, predict its behaviour, then run, repair and explain. Use the editor below freely between challenges.

Your task: pass all three checks

For x = [0.5, -1, 1.5, -2, …], the output must start [1, -2, 3, -4, …]. Check lengths 8, 32 and 35, including the last element of each vector.

1. Build your kernel

A block is a group of threads. threadIdx.x is a thread’s index within its block, blockIdx.x identifies the block, and blockDim.x is the number of threads per block. Combining them gives an index across blocks.

Keep investigating

  1. Pass all three lengths. Which element did the starting kernel miss?
  2. Inspect length 35. Jump to the last thread: why does its guard skip the memory access?
  3. Remove the bounds check and run the model. Find the first invalid access, then repair it.
  4. Try the local index. Why can a single-block test pass while length 35 fails?

Unsafe configurations are diagnosed by the model and cannot be downloaded until repaired.

What the simulation establishes

The browser computes indexing, guards, FP32 arithmetic, reads, writes, duplicate writes and unfilled outputs for the supported expressions. It does not compile CUDA, simulate SM scheduling, caches or warps, or predict time. Replay order is chosen for inspection, not GPU execution order.

Downloaded programs use CUDA C++ and require an NVIDIA GPU and CUDA Toolkit. Browser checks do not establish hardware correctness or performance.
